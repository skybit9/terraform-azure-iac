# linux-vm

Linux virtual machine with no public IP, SSH key authentication only, a NIC
level NSG, and a system assigned managed identity. The SSH key pair is
generated by Terraform and stored in Key Vault.

## Usage

```hcl
module "vms" {
  source   = "git::https://github.com/skybit9/terraform-azure-iac.git//modules/linux-vm?ref=v1.0.0"
  for_each = var.vms

  vm_name             = each.key
  vm_size             = each.value.vm_size
  resource_group_name = "rg-app-dev"
  location            = "canadacentral"
  subnet_id           = data.terraform_remote_state.networking.outputs.app_subnet_id
  key_vault_id        = data.terraform_remote_state.keyvault.outputs.key_vault_id
}
```

## Resources created (per VM)

`tls_private_key`, 2 x `azurerm_key_vault_secret`, `azurerm_network_security_group`,
`azurerm_network_interface`, `azurerm_network_interface_security_group_association`,
`azurerm_linux_virtual_machine`, plus `azurerm_role_assignment` when
`grant_vm_key_vault_read = true`.

## Required inputs

| Name | Description |
|---|---|
| `vm_name` | VM name; all child resource names derive from it |
| `resource_group_name` | Existing resource group |
| `location` | Azure region |
| `subnet_id` | Subnet for the NIC |
| `key_vault_id` | RBAC mode Key Vault for the SSH key pair |

## Permissions the deploying identity needs

| Scope | Role |
|---|---|
| Target resource group | Contributor |
| Subnet (or its VNet or RG) | `Microsoft.Network/virtualNetworks/subnets/join/action` |
| Key Vault (or its RG) | Key Vault Secrets Officer, plus Reader |
| Key Vault | User Access Administrator, only if `grant_vm_key_vault_read = true` |

## Security notes

The private key is held in Terraform state in plaintext, because Terraform
generated it. State must be encrypted, private, versioned, and readable only by
the pipeline identity.
